# Oneliner MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a mobile web journal where a trader captures a natural-language note, completes the trade later, reviews the opening week, and opts into private aggregate comparisons.

**Architecture:** Keep Next.js as the web app and API boundary. The browser uses Supabase Auth and owner-scoped Postgres rows; Postgres constraints and row-level security enforce the trade rules. A server-only OpenAI call suggests fields, while private database functions return group summaries without exposing another member's trades.

**Tech Stack:** Next.js 16.4.2 App Router, React 19.3, TypeScript, plain CSS, Supabase Auth/Postgres, OpenAI Responses API, Vitest for pure TypeScript logic, Supabase SQL tests for database rules.

**Spec:** [Oneliner MVP design](../specs/2026-10-17-oneliner-mvp-design.md)

## Global Constraints

- Keep `public/preview.html` as a visual reference; the actual app replaces the redirect at `/`.
- Mobile bottom navigation and desktop sidebar; Capture, Inbox, Review, Friends. The graphite/amber palette is provisional.
- A saved trade requires its exact original note, symbol, long/short side, entry, initial stop on the loss side, setup, and opening time. It may lack an exit.
- One entry, one initial stop, one exit. Store prices as Postgres `numeric`; derive R from the confirmed prices, with zero as breakeven. Do not add fees, broker imports, orders, or scaling.
- Weeks run Monday 00:00 UTC to the next Monday 00:00 UTC, based on `opened_at`. Completed trades alone contribute to total R, win rate, and comparison count; breakevens remain in the win-rate denominator.
- Notes, individual trades, prices, and setups remain private. Group joining is an explicit opt-in; group members see only display names and weekly total R, win rate, and completed count. Mark comparisons self-reported.
- Never expose the OpenAI key or a Supabase service key to the browser. Confirm database writes before reporting success, and preserve a failed draft for retry.
- Before changing Next.js files, read the relevant local guide under `node_modules/next/dist/docs/`, as required by `AGENTS.md`.
- Work in an isolated Git worktree when executing this plan, per the Superpowers worktree skill. Provider credentials and a Docker-compatible runtime are not present yet; do not imply live integration passed without them.

## Review Focus

- A stop equal to entry or on the profit side must fail at the database, even if the browser is bypassed (Task 1 SQL test).
- A trade opened at a UTC week boundary belongs to exactly one week; exiting it the next week does not move it (Task 4 unit test).
- A vague or malformed AI response leaves the original note intact and cannot silently fill a required value (Task 3 unit test).
- A failed save leaves the corrected fields and note available for retry and never shows a success state (Task 3 component test).
- Removed members lose group access immediately, and the old invite cannot be reused (Task 5 SQL test).

### Task 1: Trade storage and result rules

**Files:**
- Create: `supabase/migrations/202610170001_core.sql` — `profiles` and `trades`, constraints, calculated R, owner policies.
- Create: `supabase/tests/core.sql` — SQL assertions for validation, result formulas, and cross-account isolation.
- Modify: `package.json` — add Supabase CLI for migration/test commands.
- Create: `supabase/config.toml` — local project config generated by the CLI, kept minimal.

**Interfaces:**
- `profiles(id uuid primary key references auth.users, display_name text not null)`; a user may read/insert/update only their profile.
- `trades(id uuid, owner_id uuid, original_note text, symbol text, side text, entry_price numeric, stop_price numeric, setup text, opened_at timestamptz, exit_price numeric null, r_result numeric generated always as (...) stored, created_at, updated_at)`.
- `side` is `long` or `short`; require nonblank note/symbol/setup and positive prices; long stop `< entry`, short stop `> entry`. R is null until exit, then `(exit-entry)/(entry-stop)` for long or `(entry-exit)/(stop-entry)` for short.
- Browser access uses `@supabase/supabase-js` under the signed-in user's JWT; RLS restricts `trades` to `owner_id = auth.uid()` on select/insert/update/delete. `owner_id` cannot change after insert.

Assert invalid stops and an attempted owner change fail. As two simulated authenticated users, assert the second sees and changes zero first-user trades.
- [ ] **Step 2: Run `npx supabase test db` and confirm failure from missing tables.** If no Docker-compatible runtime is available, record this as an environment block and do not label the SQL verified.
- [ ] **Step 3: Implement the migration.** Add `updated_at` maintenance, RLS policies, and grants needed by the browser's authenticated role. Keep the generated result database-owned.

**Interfaces:**

### Task 5: Private group storage and access

**Files:**
- Create: `supabase/migrations/202610170002_groups.sql` — groups, invitations, memberships, policy helpers, group operations, aggregate function.
- Create: `supabase/tests/groups.sql` — two-user membership and privacy tests.

**Interfaces:**
- `groups(id uuid, owner_id uuid, name text, created_at)`; `group_invites(group_id uuid, token uuid)` readable by owner only; `group_members(group_id uuid, user_id uuid, joined_at)`.
- Exposed RPC names are `create_group(name text)`, `join_group(token uuid)`, `leave_group(group_id uuid)`, `remove_group_member(group_id uuid, member_id uuid)`, `rotate_group_invite(group_id uuid)`, `close_group(group_id uuid)`, and `group_weekly_metrics(group_id uuid, week_start timestamptz)`. Each checks `auth.uid()` and the current group state; joining inserts one membership and never returns trade rows. Create/rotate return the owner-only invite token; join/leave/remove/close return no trade data.
- Keep privileged queries in a private schema with `SECURITY DEFINER` and a fixed search path. Public RPC wrappers use invoker privileges to call only these narrow private functions. Grant no table read path from group membership to another member's `trades`.
- `group_weekly_metrics(group_id uuid, week_start timestamptz)` returns only `{ user_id, display_name, total_r, win_rate, completed_count }` for current members and completed trades opened in the normalized UTC week. Include current members with zero completions (`total_r = 0`, `win_rate = null`, `completed_count = 0`). A former member cannot call it.

- [ ] **Step 1: Add failing SQL tests.** Assert nonmembers cannot fetch metrics; members get no notes/prices/setups/trade IDs; a second member cannot select first member's trade row; removal revokes metric access and rotates the token; old token cannot rejoin; owner close and member leave revoke access.
- [ ] **Step 2: Run `npx supabase test db`; expect failure from missing group objects.** If local Postgres is unavailable, record this verification gap.
- [ ] **Step 3: Implement the migration and RLS.** Lock each function to the minimum necessary tables, validate membership inside privileged functions, and avoid returning invite tokens to nonowners.
- [ ] **Step 4: Run `npx supabase test db`; expect all core and group tests to pass.** Inspect function grants and `search_path` before accepting the privacy boundary.
- [ ] **Step 5: Commit:** `git add supabase && git commit -m "feat: protect group membership and weekly metrics"`.
